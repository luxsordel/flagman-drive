# 02. Архитектура

## Общая схема

```
 ┌──────────────┐   ┌──────────────┐   ┌──────────────┐
 │ Mobile (iOS/ │   │  Client Web  │   │ Admin panel  │
 │  Android)    │   │ (Expo Web)   │   │ React + Vite │
 └──────┬───────┘   └──────┬───────┘   └──────┬───────┘
        │   HTTPS (REST + WebSocket), JWT     │
        └──────────────┬───────────────────────┘
                ┌──────▼───────┐
                │   API        │  FastAPI, модульный монолит
                │  apps/api    │──── Worker (фоновые задачи)
                └─┬────┬────┬──┘
     ┌────────────┘    │    └─────────────┐
┌────▼─────┐     ┌─────▼────┐      ┌──────▼──────┐
│PostgreSQL│     │  Redis   │      │S3 SeaweedFS │ фото документов
│ +PostGIS │     │кэш, очер.│      │ приватный   │ и осмотров
└──────────┘     └──────────┘      └─────────────┘
        ▲  адаптеры (интерфейсы в домене)
        │
┌───────┴────────┬──────────────────┬─────────────────┐
│ Telematics     │ Payments         │ SMS / Push      │
│ → car-emulator │ → FakeProvider   │ → Console / Expo│
│ (позже StarLine│ (позже bePaid)   │ (позже SMS-шлюз)│
│  / Pandora …)  │                  │                 │
└────────────────┴──────────────────┴─────────────────┘
```

## Ключевые принципы

1. **Модульный монолит, а не микросервисы.** Один деплой бэкенда, но код разделён на модули с чёткими
   границами. Двум людям микросервисы не нужны; модуль при необходимости выносится в сервис позже.
2. **Внешний мир — через адаптеры.** Домен знает интерфейс `TelematicsGateway`, `PaymentProvider`,
   `SmsSender`, а не конкретного поставщика. Пилот работает на фейковых реализациях, бой — на реальных,
   переключение конфигом. Это главный задел на будущее.
3. **Контракт API — источник правды.** FastAPI генерирует OpenAPI → из него генерируется TypeScript-клиент
   (`packages/api-client`) для мобилки и админки. Руками типы на фронте не дублируются.
4. **Деньги и время — строго.** Суммы — целые числа в копейках (`BYN`, `Decimal` запрещён в API, только int);
   время — UTC в БД, `Europe/Minsk` только при отображении.
5. **Машина состояний аренды.** Переходы аренды описаны явно, недопустимые переходы невозможны.

## Модули бэкенда (`apps/api/src/flagman/`)

| Модуль | Ответственность |
|---|---|
| `identity` | Пользователи и профиль клиента (`/me`), вход по OTP, JWT, сессии и устройства, роли сотрудников |
| `kyc` | Документы клиента, очередь проверки, статус допуска |
| `fleet` | Машины, модели, статусы, телеметрия, команды машине |
| `geo` | Зоны (полигоны PostGIS), проверки «внутри зоны», расстояния |
| `pricing` | Тарифы, штрафы, расчёт стоимости |
| `rentals` | Бронь, поездка, завершение, осмотры — ядро продукта |
| `payments` | Карты, предавторизации, списания, чеки |
| `support` | Чат, инциденты, штрафы |
| `notifications` | Push, SMS, шаблоны на ru/en |
| `audit` | Журнал действий сотрудников и важных событий |
| `core` | Конфиг, БД, ошибки, безопасность, общие утилиты |

Каждый модуль внутри:

```
rentals/
  api.py          # роутеры FastAPI — только HTTP: валидация, вызов сервиса, ответ
  schemas.py      # Pydantic-модели запросов/ответов
  service.py      # бизнес-логика (use cases)
  domain.py       # сущности, машина состояний, правила — чистый Python без БД и HTTP
  repository.py   # доступ к БД (SQLAlchemy)
  models.py       # ORM-модели
  ports.py        # интерфейсы внешних зависимостей (если есть)
  tests/
```

**Правила зависимостей:** `api → service → domain/repository`. Модули общаются через публичные функции
сервисов или доменные события, **не** через чужие таблицы и ORM-модели.

## Машина состояний аренды

```
RESERVED ──open──▶ IN_TRIP ⇄ PARKED (ожидание)
   │                  │
   │cancel/timeout    │finish (проверки пройдены)
   ▼                  ▼
CANCELLED         FINISHED ──▶ PAID / PAYMENT_FAILED (долг)
```

Принудительное завершение оператором — отдельный переход с обязательной причиной и записью в аудит.

## Телематика и эмулятор

- `services/car-emulator` — отдельный Python-сервис, имитирует N машин в Минске: координаты, заряд,
  двери, зажигание; движется по маршрутам во время «поездки», разряжается, принимает команды.
- Обмен как у реальных облачных API телематики: **команды** — HTTP-запросы от API к эмулятору,
  **телеметрия** — подписанные (HMAC) вебхуки от эмулятора в API. Формат подписи —
  [ADR-0007](adr/0007-telematics-hmac-signing.md).
- Подключение реального поставщика = новая реализация `TelematicsGateway` + приём его вебхуков.
- Приём телеметрии — `POST /fleet/telemetry`. Его вызывает телематика, а не наши клиенты, поэтому
  эндпоинт не входит в OpenAPI и в `packages/api-client`. Разбор запроса спрятан за интерфейсом
  `TelemetryReceiver` (`fleet/ports.py`): адаптер поставщика проверяет подпись **до** разбора тела
  и превращает его формат в снимки `(id в телематике, состояние)`. Адаптер эмулятора —
  `fleet/emulator.py`. У реального поставщика будет свой адаптер со своей подписью и форматом,
  остальной `fleet` не меняется.
- Неверная подпись или метка времени — `401 invalid-signature` без причины, причина пишется в лог сервера.
  Тело больше 512 КБ — `413`, больше 1000 машин в пакете или неверный формат — `422`.
  Если `EMULATOR_TELEMETRY_SECRET` не задан, ответ `503`. Секрет команд API не получает.
- Пакет применяется в одной транзакции. Неизвестная машина и снимок «из будущего» пропускаются, остальные
  машины обновляются. В ответе и в логе — счётчики и id машин в телематике, координат в логе нет:
  по ним видно, где ездят клиенты.
- Путь входит в подпись. Обратный прокси перед API не должен переписывать путь `/fleet/telemetry`,
  иначе подпись не сойдётся.

## Парк (`fleet`)

- Модели машин (`car_models`) и машины (`cars`). У машины госномер, VIN, id в телематике и последнее
  известное состояние: точка `geography(Point, 4326)`, заряд, двери, зажигание, время снимка в UTC.
  Работа с PostGIS — через GeoAlchemy2 ([ADR-0015](adr/0015-postgis-geoalchemy2.md)).
- Статусы и переходы — в `fleet/domain.py`:

  ```
  AVAILABLE ──reserve──▶ RESERVED ──start_rental──▶ IN_RENTAL
      ▲  ◀──cancel_reservation──┘                       │
      └─────────────────────end_rental──────────────────┘
  AVAILABLE ⇄ SERVICE ⇄ OFFLINE ⇄ AVAILABLE   (send_to_service, return_from_service, go_offline, come_online)
  ```

  Переходы аренды вызывает только `rentals` (этап 3). Забронированную или арендованную машину парк сам
  не снимает с линии: сначала аренда завершается или отменяется.
- Клиенту предлагается только машина в статусе `available` со свежей телеметрией (`FLEET_TELEMETRY_MAX_AGE_SECONDS`)
  и зарядом не ниже `FLEET_MIN_BATTERY_PCT`.
- Снимок телеметрии применяется, только если он новее сохранённого. Повтор и опоздавший вебхук
  ничего не меняют ([ADR-0007](adr/0007-telematics-hmac-signing.md)).
- Время снимка — время машины. Снимок, который опережает часы API больше чем на окно ADR-0007
  (`TELEMATICS_SIGNATURE_TOLERANCE_SECONDS`, по умолчанию 5 минут), отклоняется. Снимок, опережающий
  меньше, принимается, и у этого два ограниченных следствия: машина считается свежей до
  `FLEET_TELEMETRY_MAX_AGE_SECONDS` + окно, а снимки с более ранним временем отбрасываются, пока часы
  не догонят. Пока часы синхронизированы по NTP (требование ADR-0007), обоих эффектов нет. Если окажется
  иначе, нужно хранить время прихода снимка и считать давность от него.
- Демо-парк создаёт `flagman-fleet seed` с теми же id в телематике, что у эмулятора.

## Зоны (`geo`)

- Зона — полигон `geography(Polygon, 4326)` с GIST-индексом, имя и тип: `allowed` (здесь можно завершить
  аренду) или `forbidden` (вырезает участок из разрешённых). Дыр в полигоне нет: участки вырезают
  запрещённые зоны.
- Аренда завершается в точке, если она внутри хотя бы одной активной разрешённой зоны и вне всех
  активных запрещённых. Граница разрешённой зоны разрешает, граница запрещённой запрещает: спорная точка
  решается в пользу запрета. Правило — `geo/domain.py`, точка проверяется только против зон, которые
  база нашла по индексу (`ST_Intersects`).
- Полигон проверяется до записи (Shapely, [ADR-0015](adr/0015-postgis-geoalchemy2.md)): одно внешнее кольцо,
  замкнуто, от 3 до 500 вершин, без самопересечений, все вершины в рамке пилота вокруг Минска. Каждое
  нарушение — свой тип ошибки `urn:flagman:problem:zone-polygon-*`, админка показывает по нему текст.
- `/admin/zones`: читают `operator`, `technician`, `admin`, меняет только `admin`. Зона не удаляется,
  а отключается (`disabled_at`): на неё ссылаются аудит и история. Создание, изменение и отключение пишутся
  в аудит (`zone.created`, `zone.updated`, `zone.disabled`) с типом зоны и числом вершин.
- Другие модули зовут `geo.service.can_end_rental_at` и `geo.service.distance_m` (метры на сфероиде).
- Демо-зону внутри МКАД создаёт `flagman-geo seed`.

## Тарифы (`pricing`)

- У каждой модели машины не больше одного тарифа. Цены живут в версиях: цена минуты в движении, на стоянке
  и платного ожидания брони, бесплатные минуты брони, сумма холда. Все суммы — копейки BYN (`int`).
- Изменение тарифа добавляет новую версию, которая действует с момента сохранения. Старые версии не
  меняются: аренда фиксирует версию при брони и считается по ней до конца
  ([ADR-0018](adr/0018-tariff-versions-and-rounding.md)).
- Стоимость считает чистая функция `pricing.domain.calculate`: время суммируется по видам интервалов
  (ожидание, движение, стоянка), из ожидания вычитаются бесплатные минуты, начатая минута оплачивается
  полностью. Результат — итог и строки для чека.
- `/admin/tariffs`: читают `operator` и `admin`, меняет только `admin`. В изменении передаётся номер
  версии, с которой заполняли форму; если кто-то успел сохранить новую, ответ `409 tariff-changed`.
  Создание и изменение пишутся в аудит (`tariff.created`, `tariff.updated`) с номером версии и ценами.
- Для `rentals`: `pricing.service.current_version(model_id)`, `get_version(version_id)`,
  `quote(version_id, intervals)`.
- Демо-тарифы создаёт `flagman-pricing seed` (после `flagman-fleet seed`).

## Карта клиента

- `GET /map/cars` (`fleet`) — машины, которые можно арендовать, в видимой области (четыре края) и/или
  ближайшие к точке клиента, не больше 200. `GET /map/cars/{car_id}` — карточка одной машины; машина,
  которую сейчас нельзя арендовать, отдаёт `404`, причина не раскрывается. `GET /map/zones` (`geo`) —
  активные зоны: только id, тип и полигон.
- Наружу уходят только поля карты: модель, фото, координаты, заряд, запас хода (номинальный × заряд,
  с округлением вниз), расстояние до клиента. VIN, номер, id в телематике, двери и зажигание — нет.
- Правило доступности повторено в SQL, чтобы лимит считал только доступные машины; сервис всё равно
  проверяет каждую машину правилом из `fleet/domain.py`.
- Точка клиента приходит в query string и служит только для расстояния: она не сохраняется и не пишется
  в лог (access log пишет путь без query string).
- Только вошедший клиент, KYC для просмотра не нужен. Rate limit по пользователю: машины — 300 запросов,
  зоны — 120 за 5 минут.
- Мобилка рисует карту MapLibre: нативно в iOS и Android (только dev-сборка), `maplibre-gl` в вебе —
  [ADR-0016](adr/0016-maplibre-react-native-dev-build.md).

## Стек

### Бэкенд
- Python 3.12, **FastAPI**, Pydantic v2, SQLAlchemy 2 (async) + Alembic, asyncpg
- PostgreSQL 16 + **PostGIS**, Redis 7
- Фоновые задачи: свой процесс **`flagman-worker`** — периодические задачи с advisory lock в Postgres
  ([ADR-0013](adr/0013-periodic-jobs-worker.md)). arq несовместим с `redis>=6`; очередь заданий
  (таймауты броней, повторы платежей, уведомления) выберем, когда она понадобится
- Пакеты и окружение: **uv**; линт и формат: **ruff**; типы: **mypy --strict**; тесты: **pytest** + testcontainers
- Логи — структурированные JSON (structlog), трассировка запросов через `request_id`

### Клиентское приложение (iOS, Android, веб)
- **Expo (React Native) + TypeScript**, Expo Router — один код на три платформы
- Карты: **MapLibre** (`@maplibre/maplibre-react-native`, `maplibre-gl` в вебе) + тайлы на основе OpenStreetMap
- Данные: TanStack Query + сгенерированный клиент API; состояние UI — Zustand
- i18n: i18next (ru, en)
- Сборки iOS/Android — **EAS Build в облаке** (Mac не нужен)

### Админ-панель
- React + Vite + TypeScript, TanStack Query, MapLibre (редактор зон), тот же API-клиент

### Инфраструктура
- Локально: **Docker Compose** (Postgres/PostGIS, Redis, SeaweedFS (S3), API, worker, эмулятор)
- CI: **GitHub Actions** — линт, типы, тесты, сканеры безопасности, сборка образов
- Хостинг демо: облако вне РФ (кредиты GitHub Student Pack: DigitalOcean / Azure for Students), регион ЕС.
  См. [ADR-0004](adr/0004-hosting.md)
