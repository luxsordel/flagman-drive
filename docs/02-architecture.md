# 02. Архитектура

## Общая схема

```
 ┌──────────────┐   ┌──────────────┐   ┌──────────────┐
 │ Mobile (iOS/ │   │  Client Web  │   │ Admin panel  │
 │  Android)    │   │ (Expo Web)   │   │ React + Vite │
 └──────┬───────┘   └──────┬───────┘   └──────┬───────┘
        │   HTTPS (REST + WebSocket), JWT     │
        └──────────────┬───────────────────────┘
                ┌──────▼───────┐
                │   API        │  FastAPI, модульный монолит
                │  apps/api    │──── Worker (фоновые задачи)
                └─┬────┬────┬──┘
     ┌────────────┘    │    └─────────────┐
┌────▼─────┐     ┌─────▼────┐      ┌──────▼──────┐
│PostgreSQL│     │  Redis   │      │S3 SeaweedFS │ фото документов
│ +PostGIS │     │кэш, очер.│      │ приватный   │ и осмотров
└──────────┘     └──────────┘      └─────────────┘
        ▲  адаптеры (интерфейсы в домене)
        │
┌───────┴────────┬──────────────────┬─────────────────┐
│ Telematics     │ Payments         │ SMS / Push      │
│ → car-emulator │ → FakeProvider   │ → Console / Expo│
│ (позже StarLine│ (позже bePaid)   │ (позже SMS-шлюз)│
│  / Pandora …)  │                  │                 │
└────────────────┴──────────────────┴─────────────────┘
```

## Ключевые принципы

1. **Модульный монолит, а не микросервисы.** Один деплой бэкенда, но код разделён на модули с чёткими
   границами. Двум людям микросервисы не нужны; модуль при необходимости выносится в сервис позже.
2. **Внешний мир — через адаптеры.** Домен знает интерфейс `TelematicsGateway`, `PaymentProvider`,
   `SmsSender`, а не конкретного поставщика. Пилот работает на фейковых реализациях, бой — на реальных,
   переключение конфигом. Это главный задел на будущее.
3. **Контракт API — источник правды.** FastAPI генерирует OpenAPI → из него генерируется TypeScript-клиент
   (`packages/api-client`) для мобилки и админки. Руками типы на фронте не дублируются.
4. **Деньги и время — строго.** Суммы — целые числа в копейках (`BYN`, `Decimal` запрещён в API, только int);
   время — UTC в БД, `Europe/Minsk` только при отображении.
5. **Машина состояний аренды.** Переходы аренды описаны явно, недопустимые переходы невозможны.

## Модули бэкенда (`apps/api/src/flagman/`)

| Модуль | Ответственность |
|---|---|
| `identity` | Пользователи и профиль клиента (`/me`), вход по OTP, JWT, сессии и устройства, роли сотрудников |
| `kyc` | Документы клиента, очередь проверки, статус допуска |
| `fleet` | Машины, модели, статусы, телеметрия, команды машине |
| `geo` | Зоны (полигоны PostGIS), проверки «внутри зоны», расстояния |
| `pricing` | Тарифы, штрафы, расчёт стоимости |
| `rentals` | Бронь, поездка, завершение, осмотры — ядро продукта |
| `payments` | Карты, предавторизации, списания, чеки |
| `support` | Чат, инциденты, штрафы |
| `notifications` | Push через Expo (outbox + worker), устройства, настройки, шаблоны на ru/en; SMS — после пилота |
| `audit` | Журнал действий сотрудников и важных событий |
| `core` | Конфиг, БД, ошибки, безопасность, общие утилиты |

Каждый модуль внутри:

```
rentals/
  api.py          # роутеры FastAPI — только HTTP: валидация, вызов сервиса, ответ
  schemas.py      # Pydantic-модели запросов/ответов
  service.py      # бизнес-логика (use cases)
  domain.py       # сущности, машина состояний, правила — чистый Python без БД и HTTP
  repository.py   # доступ к БД (SQLAlchemy)
  models.py       # ORM-модели
  ports.py        # интерфейсы внешних зависимостей (если есть)
  tests/
```

**Правила зависимостей:** `api → service → domain/repository`. Модули общаются через публичные функции
сервисов или доменные события, **не** через чужие таблицы и ORM-модели.

## Машина состояний аренды

```
RESERVED ──open──▶ IN_TRIP ⇄ PARKED (ожидание)
   │                  │
   │cancel/timeout    │finish (проверки пройдены)
   ▼                  ▼
CANCELLED         FINISHED ──▶ PAID / PAYMENT_FAILED (долг)
```

Принудительное завершение оператором — отдельный переход с обязательной причиной и записью в аудит.
Долг (`PAYMENT_FAILED`) после оплаты переходит в `PAID`. Переходы и запрет всех остальных —
`rentals/domain.py`.

Расчёт аренды описан в [ADR-0024](adr/0024-rental-trip-settlement.md):
- при первом открытии держится холд;
- интервалы движения и стоянки хранятся в `rental_intervals`;
- завершение проходит проверки по телеметрии, запирает машину и формирует неизменяемый чек;
- затем сумма списывается из холда с доплатой сверх него.

Итог списания хранится в `charge_status` аренды. Долгом считается любая аренда с `failed`, в том
числе отменённая бронь, у которой не прошло списание платного ожидания. Повторяет списание
`flagman-worker`.

## Телематика и эмулятор

- `services/car-emulator` — отдельный Python-сервис, имитирует N машин в Минске: координаты, заряд,
  двери, зажигание; принимает команды. Между командами парк живёт сам: стоящие машины медленно
  разряжаются, часть парка ездит по городу, разряженные заряжаются на месте (`EMULATOR_*`, README
  эмулятора).
- Обмен как у реальных облачных API телематики: **команды** — HTTP-запросы от API к эмулятору,
  **телеметрия** — подписанные (HMAC) вебхуки от эмулятора в API. Формат подписи —
  [ADR-0007](adr/0007-telematics-hmac-signing.md).
- Подключение реального поставщика = новая реализация `TelematicsGateway` + приём его вебхуков.
- Приём телеметрии — `POST /fleet/telemetry`. Его вызывает телематика, а не наши клиенты, поэтому
  эндпоинт не входит в OpenAPI и в `packages/api-client`. Разбор запроса спрятан за интерфейсом
  `TelemetryReceiver` (`fleet/ports.py`): адаптер поставщика проверяет подпись **до** разбора тела
  и превращает его формат в снимки `(id в телематике, состояние)`. Адаптер эмулятора —
  `fleet/emulator.py`. У реального поставщика будет свой адаптер со своей подписью и форматом,
  остальной `fleet` не меняется.
- Неверная подпись или метка времени — `401 invalid-signature` без причины, причина пишется в лог сервера.
  Тело больше 512 КБ — `413`, больше 1000 машин в пакете или неверный формат — `422`.
  Если `EMULATOR_TELEMETRY_SECRET` не задан, ответ `503`.
- Пакет применяется в одной транзакции. Неизвестная машина и снимок «из будущего» пропускаются, остальные
  машины обновляются. В ответе и в логе — счётчики и id машин в телематике, координат в логе нет:
  по ним видно, где ездят клиенты.
- Путь входит в подпись. Обратный прокси перед API не должен переписывать путь `/fleet/telemetry`,
  иначе подпись не сойдётся.
- Команды машине — через порт `TelematicsGateway` (`fleet/ports.py`). Адаптер эмулятора
  (`fleet/emulator.py`) шлёт `POST {EMULATOR_URL}/cars/{id в телематике}/commands`, подписанный
  отдельным `EMULATOR_COMMAND_SECRET`: утечка секрета вебхуков не даёт двигать машины. Каждая команда
  получает новый `command_id`, эмулятор отвечает `409 duplicate_command` на повтор (ADR-0007).
- Команда целиком, от подключения до ответа, ограничена `TELEMATICS_COMMAND_TIMEOUT_SECONDS` (по умолчанию
  10 с). Не удалось подключиться или телематика отказала до выполнения (4xx: неверная подпись, неизвестная
  ей машина) — `503 telematics-unavailable`, машина точно ничего не сделала. Ответа нет вовремя, ответ 5xx
  или ответ 200, который не прочитать, — `504 telematics-timeout`: команда могла выполниться, сотрудник
  сначала смотрит состояние машины. Без `EMULATOR_URL` или `EMULATOR_COMMAND_SECRET` команды отвечают `503`.

## Парк (`fleet`)

- Модели машин (`car_models`) и машины (`cars`). У машины госномер, VIN, id в телематике и последнее
  известное состояние: точка `geography(Point, 4326)`, заряд, двери, зажигание, время снимка в UTC.
  Работа с PostGIS — через GeoAlchemy2 ([ADR-0015](adr/0015-postgis-geoalchemy2.md)).
- Статусы и переходы — в `fleet/domain.py`:

  ```
  AVAILABLE ──reserve──▶ RESERVED ──start_rental──▶ IN_RENTAL
      ▲  ◀──cancel_reservation──┘                       │
      └─────────────────────end_rental──────────────────┘
  AVAILABLE ⇄ SERVICE ⇄ OFFLINE ⇄ AVAILABLE   (send_to_service, return_from_service, go_offline, come_online)
  ```

  Переходы аренды вызывает только `rentals` (этап 3). Забронированную или арендованную машину парк сам
  не снимает с линии: сначала аренда завершается или отменяется.
- Клиенту предлагается только машина в статусе `available` со свежей телеметрией (`FLEET_TELEMETRY_MAX_AGE_SECONDS`),
  с выключенным зажиганием (её никто не ведёт) и зарядом не ниже `FLEET_MIN_BATTERY_PCT`.
- Снимок телеметрии применяется, только если он новее сохранённого. Повтор и опоздавший вебхук
  ничего не меняют ([ADR-0007](adr/0007-telematics-hmac-signing.md)).
- Время снимка — время машины. Снимок, который опережает часы API больше чем на окно ADR-0007
  (`TELEMATICS_SIGNATURE_TOLERANCE_SECONDS`, по умолчанию 5 минут), отклоняется. Снимок, опережающий
  меньше, принимается, и у этого два ограниченных следствия: машина считается свежей до
  `FLEET_TELEMETRY_MAX_AGE_SECONDS` + окно, а снимки с более ранним временем отбрасываются, пока часы
  не догонят. Пока часы синхронизированы по NTP (требование ADR-0007), обоих эффектов нет. Если окажется
  иначе, нужно хранить время прихода снимка и считать давность от него.
- Демо-парк создаёт `flagman-fleet seed` с теми же id в телематике, что у эмулятора.

### Парк для сотрудников

- `GET /admin/fleet/cars` — весь парк по госномеру с полным состоянием (точка, заряд, двери, зажигание,
  блокировка двигателя, время снимка) и фильтрами `status` (можно несколько) и `low_battery` (заряд ниже
  `FLEET_MIN_BATTERY_PCT`: такую машину не сдают, она ждёт зарядки). `GET /admin/fleet/cars/{car_id}` —
  одна машина. Читают `operator`, `technician`, `admin`. В ответе ещё пороги (`rules`) и время сервера
  (`as_of`): свежесть телеметрии меняется со временем без событий, админка считает её сама по часам
  сервера.
- Изменения приходят по WebSocket `/admin/fleet/stream`: снимок после входа, дальше изменившиеся машины
  и результаты ручных команд. Рассылка между процессами API — `LISTEN/NOTIFY` Postgres, уведомление
  уходит только после коммита. Протокол, аутентификация, коды закрытия и переподключение —
  [ADR-0017](adr/0017-fleet-stream-websocket.md). Любое изменение машины идёт через сервис `fleet`,
  иначе сотрудники его не увидят.
- Ручные команды — `POST /admin/fleet/cars/{car_id}/commands`: `open`, `close`, `lock_engine`,
  `unlock_engine`. Их шлют `operator`, `technician` (обслуживает машины на месте) и `admin`.
  Кроме токена проверяется живая сессия в БД (`require_live_staff_session`): после выхода, отзыва сессии
  или отключения сотрудника команды не проходят сразу, а не через 15 минут жизни токена.
  Комментарий обязателен (3–300 символов, без телефонов и почты: он уходит в аудит). Машине в статусе
  `reserved` или `in_rental` команда уходит только с `confirm_active_rental`, иначе `409
  car-in-active-rental` и ничего не отправляется: клиента можно запереть в машине или снаружи. На этапе 3
  правило перейдёт на активную аренду. Rate limit — 20 команд в минуту на сотрудника.
- Каждая команда, дошедшая до телематики, пишется в аудит (`car.command_sent`: команда, исход, причина
  отказа, `command_id`, статус машины, была ли аренда, комментарий) и рассылается всем в поток — при любом
  исходе. Ответ телематики с состоянием машины сразу применяется как снимок. Пока машина думает,
  транзакция не открыта.

## Зоны (`geo`)

- Зона — полигон `geography(Polygon, 4326)` с GIST-индексом, имя и тип: `allowed` (здесь можно завершить
  аренду) или `forbidden` (вырезает участок из разрешённых). Дыр в полигоне нет: участки вырезают
  запрещённые зоны.
- Аренда завершается в точке, если она внутри хотя бы одной активной разрешённой зоны и вне всех
  активных запрещённых. Граница разрешённой зоны разрешает, граница запрещённой запрещает: спорная точка
  решается в пользу запрета. Правило — `geo/domain.py`, точка проверяется только против зон, которые
  база нашла по индексу (`ST_Intersects`).
- Полигон проверяется до записи (Shapely, [ADR-0015](adr/0015-postgis-geoalchemy2.md)): одно внешнее кольцо,
  замкнуто, от 3 до 500 вершин, без самопересечений, все вершины в рамке пилота вокруг Минска. Каждое
  нарушение — свой тип ошибки `urn:flagman:problem:zone-polygon-*`, админка показывает по нему текст.
- `/admin/zones`: читают `operator`, `technician`, `admin`, меняет только `admin`. Зона не удаляется,
  а отключается (`disabled_at`): на неё ссылаются аудит и история. Создание, изменение и отключение пишутся
  в аудит (`zone.created`, `zone.updated`, `zone.disabled`) с типом зоны и числом вершин.
- Другие модули зовут `geo.service.can_end_rental_at` и `geo.service.distance_m` (метры на сфероиде).
- Демо-зону внутри МКАД создаёт `flagman-geo seed`.

## Тарифы (`pricing`)

- У каждой модели машины не больше одного тарифа. Цены живут в версиях: цена минуты в движении, на стоянке
  и платного ожидания брони, бесплатные минуты брони, сумма холда. Все суммы — копейки BYN (`int`).
- Изменение тарифа добавляет новую версию, которая действует с момента сохранения. Старые версии не
  меняются: аренда фиксирует версию при брони и считается по ней до конца
  ([ADR-0018](adr/0018-tariff-versions-and-rounding.md)).
- Стоимость считает чистая функция `pricing.domain.calculate`: время суммируется по видам интервалов
  (ожидание, движение, стоянка), из ожидания вычитаются бесплатные минуты, начатая минута оплачивается
  полностью. Результат — итог и строки для чека.
- `/admin/tariffs`: читают `operator` и `admin`, меняет только `admin`. В изменении передаётся номер
  версии, с которой заполняли форму; если кто-то успел сохранить новую, ответ `409 tariff-changed`.
  Создание и изменение пишутся в аудит (`tariff.created`, `tariff.updated`) с номером версии и ценами.
- Для `rentals`: `pricing.service.current_version(model_id)`, `get_version(version_id)`,
  `quote(version_id, intervals)`.
- Демо-тарифы создаёт `flagman-pricing seed` (после `flagman-fleet seed`).

## Платежи (`payments`)

- Провайдер — за портом `PaymentProvider` (`payments/ports.py`). В пилоте — `FakeProvider` внутри API:
  своя страница ввода карты, тестовые номера карт, деньги не двигаются
  ([ADR-0019](adr/0019-payment-port-and-fake-provider.md)). Без `PAYMENTS_PROVIDER` привязка карт и платежи
  отвечают `503 payments-unavailable`.
- Привязка: `POST /payment-cards/bindings` возвращает страницу провайдера. Номер карты вводится там и
  к нам не попадает. Итог приходит подписанным вебхуком (`POST /payments/webhooks/fake`, вне OpenAPI),
  клиент узнаёт его из `GET /payment-cards/bindings/{id}`. Адрес возврата — только наше приложение или
  наш веб-клиент.
- Храним маску, платёжную систему, срок и токен провайдера, зашифрованный `PAYMENTS_TOKEN_ENCRYPTION_KEY`.
  Токен не отдаётся клиенту и не логируется. Клиент видит и меняет только свои карты: чужая — `404`.
- Для `rentals`: `has_usable_card`, `hold`, `capture`, `charge`, `void`, `refund`. Операции идемпотентны по
  ключу вызывающего, у каждой статус (`pending`, `succeeded`, `declined`, `failed`) и журнал попыток.
  Функции открывают свои транзакции: сетевой вызов провайдера идёт вне транзакции. Каждый исход операции
  пишется в аудит (`payment.*`).

## Уведомления (`notifications`)

- Push клиенту через Expo Push Service за портом `PushProvider` (`notifications/ports.py`); для разработки
  и тестов — `FakePushProvider`. Выбор — `NOTIFICATIONS_PROVIDER`, настройки читает только worker
  ([ADR-0020](adr/0020-push-notifications-outbox.md)).
- Другие модули вызывают `notifications.service.notify_client(db, user_id, notification, now)` в своей
  транзакции. Уведомление ложится в таблицу `notification_outbox`; одно событие по одной аренде — один раз
  (`dedup_key`). Отправляет `flagman-worker` раз в несколько секунд, с повторами (до 5 попыток).
- Текст собирается на сервере по шаблонам ru/en на языке профиля. В уведомлении только числа и id аренды.
- События брони: «бронь истекла» — при отмене брони по сроку (и воркером, и при обращении к ней), «бронь
  истекает» — минутной задачей воркера за `RENTAL_RESERVATION_REMINDER_MINUTES` (5) до конца. Разрешение
  на уведомления приложение спрашивает при первой брони. События поездки и оплаты подключаются в #111.
- Устройство — одно на сессию входа: `PUT/DELETE /me/push-device`. После выхода или отзыва сессии push
  на телефон не идут, устройство удаляется.
- Настройки — `GET/PATCH /me/notification-preferences`: бронь можно отключить, поездку и оплату нельзя.

## Карта клиента

- `GET /map/cars` (`fleet`) — машины, которые можно арендовать, в видимой области (четыре края) и/или
  ближайшие к точке клиента, не больше 200. `GET /map/cars/{car_id}` — карточка одной машины; машина,
  которую сейчас нельзя арендовать, отдаёт `404`, причина не раскрывается. `GET /map/zones` (`geo`) —
  активные зоны: только id, тип и полигон.
- Наружу уходят только поля карты: модель, фото, координаты, заряд, запас хода (номинальный × заряд,
  с округлением вниз), расстояние до клиента, цена минуты в движении и на стоянке по текущему тарифу
  модели. VIN, номер, id в телематике, двери и зажигание — нет.
- Машины модели без тарифа на карте не показываются: их не сдают. Модели с тарифом и цены роутер карты
  берёт из `pricing.service.current_versions` и передаёт в `fleet` фильтром запроса. `pricing` сам читает
  модели из `fleet.service`, поэтому `fleet.service` от `pricing` не зависит: связывает их только роутер.
- Правило доступности повторено в SQL, чтобы лимит считал только доступные машины; сервис всё равно
  проверяет каждую машину правилом из `fleet/domain.py`.
- Точка клиента приходит в query string и служит только для расстояния: она не сохраняется и не пишется
  в лог (access log пишет путь без query string).
- Только вошедший клиент, KYC для просмотра не нужен. Rate limit по пользователю: машины — 300 запросов,
  зоны — 120 за 5 минут.
- Мобилка рисует карту MapLibre: нативно в iOS и Android (только dev-сборка), `maplibre-gl` в вебе —
  [ADR-0016](adr/0016-maplibre-react-native-dev-build.md).

## Аренды (`rentals`)

- Аренда хранит клиента, машину, статус и метки времени: бронь, конец бесплатного ожидания, конец
  брони, начало поездки, окончание. Отменённая бронь хранит причину: `client` или `expired`.
  Аренда фиксирует версию тарифа модели на момент брони (`pricing.service.current_version`):
  изменение тарифа потом её цену не меняет.
- У клиента и у машины не больше одной аренды в `reserved`, `in_trip` или `parked`. Это
  гарантируют частичные уникальные индексы, а не только проверка в сервисе: параллельные запросы
  не обходят правило.
- **Бронь** — `POST /rentals`. Можно только клиенту с одобренным KYC
  (`kyc.service.get_admission_status`), не заблокированному (`identity.service.is_client_blocked`,
  флаг ставит оператор в #112) и без другой активной аренды. Машина должна быть доступна по правилу
  `fleet` (`fleet.service.reserve_car`, проверка под блокировкой строки), и у её модели должен быть
  тариф. Недоступная машина отвечает `404 car-not-found`, как на карте. Rate limit — 20 броней в час на клиента.
- Бронь бесплатна столько минут, сколько даёт тариф (`free_waiting_minutes`), потом платная до
  `RENTAL_MAX_RESERVATION_MINUTES` (45) от начала. Если бесплатных минут в тарифе больше, бесплатна
  вся бронь. Затем бронь отменяется по сроку: при обращении к
  ней или задачей воркера раз в минуту ([ADR-0022](adr/0022-rental-reservation-timeout.md)).
  В ответе есть `as_of` — время сервера, от него приложение считает обратный отсчёт.
- `GET /rentals/current` — активная аренда клиента, чтобы приложение вернулось к ней после
  перезапуска. Чужая аренда на любом эндпоинте отвечает `404 rental-not-found`.
- **Осмотр** — `/rentals/{id}/inspections/{stage}`: `before` пока машина забронирована, `after`
  во время поездки (#111). Это 4–8 фото и отметки повреждений (сторона и комментарий до 300
  символов), потом `submit`. Фото и повреждения нельзя удалить или заменить ни до, ни после
  отправки: это доказательство.
- Фото принимаются и хранятся по правилам документов KYC
  ([ADR-0012](adr/0012-kyc-document-storage.md)):
  - сырое тело, тип по содержимому, перекодирование в JPEG без метаданных;
  - ключ `inspections/<rental_id>/<uuid>.jpg`;
  - ссылки на 5 минут с `no-store`.

  Хранилище и обработка фото общие: `core/storage.py`, `core/photos.py`.
- **Команды** — `POST /rentals/{id}/commands` (`open`, `close`) с координатами клиента. Сервер
  проверяет:
  - аренда активна и принадлежит клиенту;
  - KYC одобрен, клиент не заблокирован;
  - осмотр отправлен;
  - снимок машины свежий;
  - до машины не больше `RENTAL_COMMAND_MAX_DISTANCE_M` (50) м.

  Команда идёт через `fleet.service.RentalCarCommander` и пишется в аудит с клиентом и `rental_id`.
  Координаты клиента не сохраняются и не логируются. Первое успешное `open` переводит аренду в
  `in_trip`, машину — в `in_rental`. Пока машина отвечает, бронь не истекает и не отменяется
  (`command_until`). Ошибка телематики аренду не меняет. Rate limit — 10 команд в минуту на клиента.

## Стек

### Бэкенд
- Python 3.12, **FastAPI**, Pydantic v2, SQLAlchemy 2 (async) + Alembic, asyncpg
- PostgreSQL 16 + **PostGIS**, Redis 7
- Фоновые задачи: свой процесс **`flagman-worker`** — периодические задачи с advisory lock в Postgres
  ([ADR-0013](adr/0013-periodic-jobs-worker.md)), у каждой свой интервал. arq несовместим с `redis>=6`.
  Задания по событию идут через таблицу-outbox в Postgres: модуль пишет в неё в своей транзакции, worker
  отправляет и повторяет — так сделаны push-уведомления ([ADR-0020](adr/0020-push-notifications-outbox.md)).
  Брони истекают задачей воркера раз в минуту и проверкой при каждом обращении
  ([ADR-0022](adr/0022-rental-reservation-timeout.md))
- Пакеты и окружение: **uv**; линт и формат: **ruff**; типы: **mypy --strict**; тесты: **pytest** + testcontainers
- Логи — структурированные JSON (structlog), трассировка запросов через `request_id`

### Клиентское приложение (iOS, Android, веб)
- **Expo (React Native) + TypeScript**, Expo Router — один код на три платформы
- Карты: **MapLibre** (`@maplibre/maplibre-react-native`, `maplibre-gl` в вебе) + тайлы на основе OpenStreetMap
- Данные: TanStack Query + сгенерированный клиент API; состояние UI — Zustand
- i18n: i18next (ru, en)
- Сборки iOS/Android — **EAS Build в облаке** (Mac не нужен)

### Админ-панель
- React + Vite + TypeScript, TanStack Query, MapLibre (редактор зон), тот же API-клиент

### Инфраструктура
- Локально: **Docker Compose** (Postgres/PostGIS, Redis, SeaweedFS (S3), API, worker, эмулятор)
- CI: **GitHub Actions** — линт, типы, тесты, сканеры безопасности; образы стенда собираются и публикуются
  в GHCR только при выкладке
- Демо-стенд: один дроплет DigitalOcean во Франкфурте, Compose + Caddy, выкладка по кнопке или тегу.
  См. [ADR-0004](adr/0004-hosting.md), [ADR-0021](adr/0021-demo-stand-digitalocean-ghcr.md),
  [docs/08-demo-stand.md](08-demo-stand.md)
