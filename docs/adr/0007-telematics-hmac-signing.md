# ADR-0007. Подпись запросов телематики: HMAC-SHA256 + метка времени

- Статус: принято
- Дата: 2026-10-22

## Контекст
API и телематика обмениваются в обе стороны: **команды** (открыть, закрыть, заблокировать двигатель) идут
HTTP-запросами от API к телематике, **телеметрия** приходит вебхуками от телематики в API
(см. [02-architecture](../02-architecture.md)). Пока телематика — эмулятор `services/car-emulator` (#7),
позже — облачный API реального поставщика.

Команда машине — самое опасное действие в системе, поэтому каждый запрос должен быть аутентифицирован,
защищён от подмены и от повтора ([03-security](../03-security.md): «подпись HMAC + метка времени»).
Нужен один формат, который одинаково реализуют эмулятор и API.

## Решение
- Два заголовка:
  - `X-Flagman-Timestamp` — unix-время в секундах, только цифры ASCII;
  - `X-Flagman-Signature` — `sha256=<hex>`, HMAC-SHA256 от строки
    `timestamp \n METHOD \n target \n body`, где `target` — путь запроса вместе с query-строкой
    (байты как в запросе), `body` — сырое тело (для GET — пустое).
- Метод и путь входят в подпись, чтобы перехваченный запрос нельзя было отправить на другую машину или
  другой эндпоинт.
- Подпись проверяется до разбора тела, сравнение — за постоянное время (`hmac.compare_digest`).
  Ответ на неверную подпись — `401 invalid_signature` без указания причины.
- Допустимое расхождение часов — ±300 с (настройка). Запрос вне окна отклоняется.
- Защита от повтора команд: в теле обязателен `command_id` (UUID). Получатель помнит id в течение
  2 × окна и отвечает `409 duplicate_command` на повтор. Отклонённая команда тоже «занимает» id.
- Секреты разные для команд и для телеметрии: утечка секрета вебхуков не даёт права слать команды.
  Минимальная длина — 32 символа, хранятся только в окружении (`.env`).
- В эмуляторе проверка сделана ASGI-middleware: защищены все пути, кроме явного списка исключений
  (`/health`), так что новый эндпоинт нельзя случайно оставить без подписи.
- Эталонный вектор для проверки реализации на стороне API — в `services/car-emulator/tests/test_signing.py`.

## Альтернативы
- **Подпись только тела** (как у многих платёжных вебхуков) — проще, но GET-запросы и команды можно
  переадресовать на другой путь.
- **mTLS** — сильнее, но требует своей PKI и выпуска сертификатов; для пилота избыточно, а реальные
  поставщики телематики чаще дают токены или HMAC.
- **Статический Bearer-токен** — не защищает от повтора и подмены тела; утечка из лога сразу даёт полный доступ.
- **Хранить nonce для телеметрии** — для пилота не нужно: повтор вебхука в пределах окна лишь повторно
  присылает тот же снимок состояния.

## Последствия
- API должен реализовать ту же проверку для вебхуков и подпись для команд — модуль `fleet`,
  реализация `TelematicsGateway` для эмулятора.
- Повтор вебхука телеметрии внутри окна возможен: на стороне API — дедупликация по
  `(car_id, updated_at)`.
- Часы API и телематики должны быть синхронизированы (NTP) с точностью лучше окна.
- Реальный поставщик почти наверняка подписывает иначе: для него пишется свой адаптер, этот формат
  остаётся контрактом только с эмулятором.
- Список виденных `command_id` хранится в памяти: после перезапуска эмулятора повтор в пределах окна
  снова пройдёт. Для эмулятора допустимо; для боевой интеграции — вопрос к поставщику.
