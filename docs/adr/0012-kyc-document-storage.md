# ADR-0012. Документы KYC: загрузка, очистка фото и подписанные ссылки

- Статус: принято
- Дата: 2026-10-23

## Контекст
Клиент загружает фото прав (обе стороны), паспорта и селфи с правами (#34). Требования
[03-security](../03-security.md): приватный бакет, тип файла определяется по содержимому, лимит размера,
удаление EXIF, просмотр только по подписанным ссылкам не дольше 5 минут. Хранилище — SeaweedFS по S3 API
([ADR-0005](0005-object-storage-seaweedfs.md)). Это первый модуль, который принимает файлы от клиента.

Фото с телефона несут в метаданных координаты съёмки, модель телефона, время, иногда миниатюру исходного
кадра. В метаданных могут быть и данные, которых не видно на самом фото.

## Решение
- **Фото — сырое тело `PUT /kyc/documents/{kind}`**, а не multipart-форма. Starlette сначала пишет
  multipart-файл целиком во временный файл и только потом отдаёт его обработчику. У контейнера API `/tmp`
  лежит в памяти (tmpfs), так что обойти лимит размера можно было бы, просто прислав большой файл.
  Сырое тело читается потоком, и чтение обрывается, как только превышен лимит (10 МБ), в том числе при
  chunked-загрузке без `Content-Length`.
- **Тип — по содержимому через Pillow**: принимаются только JPEG, PNG и WebP, остальное — 415. Имя файла и
  `Content-Type` клиента не учитываются. Размер в пикселях проверяется по заголовку до распаковки
  (не больше 30 Мп), чтобы маленький файл не раскрылся в гигабайты памяти.
- **Фото всегда перекодируется в JPEG** (качество 90) и сохраняется без метаданных. Удалять отдельные
  известные теги ненадёжно: метаданные бывают в EXIF, XMP, ICC, комментариях, текстовых блоках PNG.
  После перекодирования в файле остаются только пиксели. Ориентацию из EXIF применяем к пикселям до
  удаления, иначе фото окажется повёрнутым. Обработка идёт в отдельном потоке, не блокируя event loop.
- **Ключ объекта** — `kyc/<application_id>/<случайный uuid>.jpg`, без персональных данных. Каждая загрузка
  получает новый ключ, а старый объект удаляется после фиксации в базе. Поэтому выданная раньше ссылка
  никогда не покажет новое фото.
- **Ссылки** — presigned GET на 5 минут, подписываются локально, без запроса к хранилищу. Подпись S3
  включает хост, поэтому есть две настройки: `S3_ENDPOINT_URL` (куда ходит API) и `S3_PUBLIC_URL`
  (по какому адресу ссылку откроет клиент). При `API_ENV=prod` публичный адрес обязан быть `https`.
  Ссылки, ключи и подписи не пишутся в логи.
- **Заявка** — одна на клиента (`kyc_applications`), документы — по одному каждого вида (`kyc_documents`).
  Статусы и переходы описаны в `kyc/domain.py`. Загружать документы можно в `not_submitted` и
  `rejected`; после отклонения клиент меняет только то, что нужно, остальные документы засчитываются.
  Загрузка и подача заявки берут блокировку строки заявки, поэтому фото нельзя подменить между проверкой
  комплектности и сменой статуса.
- **Без настроенного хранилища** (нет `S3_ACCESS_KEY` / `S3_SECRET_KEY`) API работает, а загрузка и
  ссылки отвечают 503. Так же сделано для SMS: разработчику без SeaweedFS не нужно ничего настраивать.
- Статус допуска для других модулей — `kyc.service.get_admission_status`. В аренду допускает только
  `approved`.

## Альтернативы
- **Multipart с `UploadFile`** — привычнее для клиентов, но лимит размера срабатывает только после того,
  как файл уже целиком в tmpfs (см. выше).
- **Загрузка клиентом напрямую в S3 по presigned PUT** — меньше нагрузки на API, но файл попадает в
  бакет непроверенным и с EXIF, и нужна отдельная фоновая очистка. Для пилота лишняя сложность.
- **Удаление EXIF без перекодирования** (piexif и подобные) — не трогает качество, но чистит только EXIF
  и только в JPEG.
- **Принимать HEIC** — нужна `pillow-heif` с нативной libheif. Мобильное приложение (#38) и так может
  отдавать JPEG (`expo-image-picker` / `expo-image-manipulator`).

## Последствия
- Повторное сжатие немного снижает качество; для проверки документов 90 достаточно.
- Возможны «осиротевшие» объекты (процесс упал между записью в хранилище и в базу). Они без ПД в ключе и
  недоступны без подписи; при необходимости — периодическая чистка по префиксу `kyc/`.
- Для демо с телефона `S3_PUBLIC_URL` должен указывать на адрес, доступный телефону (сейчас SeaweedFS
  слушает только `127.0.0.1`). На сервере пилота перед выкладкой нужен `https`-адрес хранилища за
  reverse proxy: иначе API с `API_ENV=prod` и ключами S3 не запустится.
- Удалить клиента с заявкой KYC нельзя, пока не удалены документы: внешний ключ без `ON DELETE CASCADE`
  не даст оставить фото в хранилище без записи о них.
- Просмотр документов операторами (#35) использует те же ключи и ссылки.
