# ADR-0021. Демо-стенд: DigitalOcean, образы в GHCR, выкладка по кнопке

- Статус: принято
- Дата: 2026-10-27

## Контекст
Задача #123: руководство открывает админку по ссылке и ставит приложение на свой телефон, а не смотрит на
ноутбук разработчика. ADR-0004 уже решил «один VPS в ЕС, Docker Compose + Caddy», но не выбрал провайдера
и не описал, как код попадает на сервер. Ограничения:
- денег нет — только кредиты GitHub Student Pack;
- стенд на тестовых данных, без реальных денег и SMS (`docs/01-vision-and-mvp.md`);
- наружу — только 80/443 и SSH по ключу, секреты — только на сервере и в секретах GitHub (`docs/03-security.md`);
- выкладка не на каждый коммит в `main`, откат на предыдущую версию должен быть проверен;
- аккаунта Apple Developer нет.

## Решение

### Сервер
- **DigitalOcean**, один дроплет во Франкфурте (`fra1`): Basic, 2 vCPU / 4 ГБ, Ubuntu 24.04 LTS. Кредита
  Student Pack хватает на весь пилот. 4 ГБ — запас для Postgres, API, воркера, эмулятора и SeaweedFS сразу.
- **Cloud Firewall DigitalOcean**: входящие только 22, 80, 443. SSH — только по ключу, вход под `root` закрыт,
  выкладка идёт от пользователя `deploy`.
- Один домен `STAND_DOMAIN` и четыре поддомена за одним Caddy с автоматическим HTTPS:
  `admin.` (админка; `/staff/` и `/admin/` проксируются в API), `app.` (веб-версия приложения),
  `api.` (API для приложения), `s3.` (подписанные ссылки на фото, SeaweedFS S3). Поддомены одного домена —
  один «сайт» для cookie: refresh-cookie с `SameSite=Strict` доходит до `api.` из `app.`.
- Postgres, Redis, SeaweedFS и эмулятор — только во внутренней сети Compose, без опубликованных портов.

### Образы и выкладка
- Три образа в **GHCR** репозитория: `api` (он же воркер и миграции, ADR-0013), `car-emulator`, `web`
  (Caddy со статикой админки и веб-версии приложения). Тег — SHA коммита.
- Workflow `stand.yml` запускается **кнопкой** (`workflow_dispatch`) или **тегом** `stand-v*`, не на каждый
  коммит в `main`. Он собирает образы, публикует их и по SSH запускает на сервере `infra/stand/bin/deploy.sh <тег>`.
- `deploy.sh`: вход в GHCR токеном этого запуска (после выкладки — выход), `pull`, миграции отдельным
  одноразовым сервисом `migrate` до старта API, `up -d`, ожидание `/ready`. Выложенные теги дописываются
  в журнал на сервере — из него берётся предыдущий тег для отката.
- **Откат** — тот же workflow с тегом предыдущего образа. Если у старого образа другая голова Alembic,
  `deploy.sh` сначала откатывает схему текущим образом (`alembic downgrade <голова старого>`), потом
  меняет образы. Миграции, у которых `downgrade` теряет данные, откатываются восстановлением из копии.

### Секреты
- Секреты приложения (ключи JWT и TOTP, пароли БД и Redis, ключи S3, код OTP стенда, тестовые сотрудники) —
  только в `/opt/flagman/stand.env` на сервере (`0600`, владелец `deploy`). Они создаются один раз руками
  и через GitHub не проходят.
- В GitHub, в Environment `stand`, — только доступ к серверу: SSH-ключ выкладки, адрес, `known_hosts`;
  `STAND_DOMAIN` — переменная окружения, не секрет. Права Environment ограничивают, кто может выкладывать.

### Данные
- Вход по OTP — общий код для заранее заведённых тестовых номеров (`SMS_BACKEND=fixed`, `docs/03-security.md`).
- Резервная копия Postgres (`pg_dump`) раз в сутки в том на сервере, хранение `BACKUP_KEEP_DAYS` дней.
  Фото в SeaweedFS не копируются: они тестовые, а KYC можно пройти заново.

### Телефоны
- **Android** — APK из EAS Build (профиль `stand`), ставится по ссылке.
- **iOS** — без аккаунта Apple Developer TestFlight недоступен: на iPhone открывают веб-версию с `app.`
  (её можно добавить на экран «Домой»). Профиль EAS для TestFlight добавим, когда появится аккаунт.

## Альтернативы
- **Azure for Students** — кредит меньше и сгорает через 12 месяцев, дешёвые B-серии
  тормозят при исчерпании burst-кредитов.
- **Сборка на сервере** (`git pull && docker compose build`) — на 4 ГБ сборка Node мешает работающему стенду,
  и образ на стенде нельзя повторить: откат превращается в пересборку старого коммита.
- **Watchtower или выкладка на каждый коммит в `main`** — стенд показывают руководству, он не должен меняться
  посреди показа.
- **Docker Hub** — лимиты на скачивание и отдельный аккаунт; GHCR бесплатен для репозитория и доступен
  токеном запуска workflow.
- **Секреты приложения в GitHub с передачей на сервер при каждой выкладке** — ещё одно место, откуда они
  могут утечь (логи workflow, сторонние actions), а выигрыша для одного сервера нет.

## Последствия
- Стенд — одна машина: сбой дроплета = стенд недоступен до восстановления из копии. Для пилота приемлемо.
- Пользователь `deploy` в группе `docker` фактически равен `root` на сервере. Поэтому его ключ лежит
  только в Environment `stand`, а выкладку запускают только участники с правами на Environment.
- Миграции нужно писать так, чтобы `downgrade` работал — иначе откат идёт через восстановление из копии.
- Образ `web` собирается под конкретный `STAND_DOMAIN`: адрес API вшивается в веб-версию приложения при сборке.
  Смена домена = новая сборка.
- Данные хранятся в ЕС. Перед реальными данными граждан РБ — оценка по Закону № 99-З (ADR-0004).
- Порядок работы со стендом — `docs/08-demo-stand.md`.
