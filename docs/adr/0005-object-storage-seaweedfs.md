# ADR-0005. Объектное хранилище: SeaweedFS вместо MinIO

- Статус: принято
- Дата: 2026-10-22

## Контекст
Для фото документов и осмотров нужно S3-совместимое хранилище с приватным бакетом и подписанными ссылками
(см. [03-security](../03-security.md)). Изначально в архитектуре был MinIO.

При работе над локальной инфраструктурой (#2) выяснилось, что MinIO больше не публикует образы: `minio/minio`
и `minio/mc` на Docker Hub и `quay.io/minio/*` недоступны ни по `latest`, ни по закреплённым тегам.
Остаётся сборка из исходников без обновлений безопасности — это свой Dockerfile, долгая сборка на каждой
машине и замороженная версия.

Бэкенд работает с хранилищем только по протоколу S3, поэтому конкретная реализация заменяема.

## Решение
- Локально и на демо-стенде — **SeaweedFS** (Apache-2.0), образ `chrislusf/seaweedfs` с закреплённой версией.
  Один контейнер `weed server -s3` (master + volume + filer + S3-шлюз).
- Ключ администратора — через `AWS_ACCESS_KEY_ID` / `AWS_SECRET_ACCESS_KEY` из `.env`. С ключами анонимный
  доступ запрещён (проверено: 403 на чтение, листинг и создание бакета).
- Приватный бакет создаётся одноразовым init-контейнером через `weed shell` (`s3.bucket.create`).
- Телеметрия SeaweedFS отключена (`-master.telemetry=false`).
- Код бэкенда использует только S3 API (boto3/aioboto3); адрес, ключи и бакет — в конфиге.

## Альтернативы
- **MinIO из исходников** — работает, но сборка на каждой машине и нет обновлений безопасности.
- **RustFS** (Apache-2.0) — почти полная совместимость с API MinIO, но проект молодой (1.0 вышел недавно).
- **Garage** (AGPL) — лёгкий, но требует ручной настройки раскладки кластера при первом запуске,
  что усложняет «одну команду»; AGPL — лишние вопросы при будущем коммерческом использовании.
- **Облачный S3** (AWS, DigitalOcean Spaces) — не работает офлайн и требует карту для оплаты; для локальной
  разработки не подходит, но может заменить SeaweedFS на боевом стенде без изменения кода.

## Последствия
- Локальная инфраструктура поднимается из публичных образов одной командой.
- Подпись S3 включает хост: подписанные ссылки должны генерироваться для того адреса, по которому их откроет
  клиент. В API понадобится отдельная настройка публичного адреса хранилища (внутренний `seaweedfs:8333`
  для сервера, публичный — для ссылок).
- Без заданных ключей SeaweedFS открывает S3 анонимно, поэтому compose падает, если ключи не заданы.
- У SeaweedFS есть платная Enterprise-версия; если открытую перестанут развивать — повторяем замену
  (S3 API это позволяет).
- Перед боевым запуском — пересмотреть: свой SeaweedFS с бэкапами или управляемый S3 (с учётом
  требований к месту хранения из [ADR-0004](0004-hosting.md)).
