# ADR-0002. Модульный монолит с адаптерами внешних систем

- Статус: принято
- Дата: 2026-10-21

## Контекст
Двое разработчиков, нет бюджета на инфраструктуру. Но продукт должен вырасти в реальный сервис
с реальной телематикой, платежами и большей командой.

## Решение
Один бэкенд-сервис, разделённый на модули с явными границами (см. [архитектуру](../02-architecture.md)).
Внешние системы (телематика, платежи, SMS, push) — через интерфейсы (ports) с подменяемыми реализациями (adapters).
Пилот работает на фейковых адаптерах.

## Альтернативы
- **Микросервисы** — для двух человек это кратный рост сложности деплоя, отладки и согласованности данных.
- **Монолит без границ** — быстро в начале, спагетти через полгода; модули не вынести.

## Последствия
- Правило: модуль не обращается к чужим таблицам и ORM-моделям. Нарушение — повод для отказа в ревью.
- Проверка границ автоматизируется (import-linter в CI).
- Подключение реального поставщика не требует переписывать бизнес-логику.
