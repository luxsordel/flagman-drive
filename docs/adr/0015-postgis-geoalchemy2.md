# ADR-0015. Работа с PostGIS через GeoAlchemy2

- Статус: принято
- Дата: 2026-10-24

## Контекст
В этапе 2 в API появляются геоданные: координаты машин (#90), зоны завершения аренды в виде полигонов (#92),
поиск машин в области карты и рядом с клиентом (#94). PostGIS уже включён миграцией `enable_postgis`, но
SQLAlchemy сам не знает типов `geography` и `geometry` и функций `ST_*`.

Ограничения проекта: никакого SQL из строк (`docs/03-security.md`), mypy --strict, проверка в CI, что
миграции совпадают с моделями (`tests/test_migrations.py`).

## Решение
- Берём **GeoAlchemy2**: типы `Geography` и `Geometry` для моделей и миграций, функции PostGIS через
  `sqlalchemy.func` с привязанными параметрами.
- Координаты храним как `geography(Point, 4326)`: расстояния и радиусы считаются в метрах на сфере, без
  перепроецирования. Для `ST_X`/`ST_Y` значение приводится к `geometry` в запросе.
- Точки пишем через `ST_SetSRID(ST_MakePoint(lon, lat), 4326)` с параметрами, не через WKT-строку.
  Порядок — долгота, затем широта, как в PostGIS и GeoJSON.
- Сырое значение `geography` в ORM не загружаем. Координаты читаются как числа, поэтому драйверу asyncpg
  не нужен кодек для типа PostGIS.
- Пространственные индексы объявляем явно (`Index(..., postgresql_using="gist")`, `spatial_index=False`
  у типа). Так индекс виден в модели и в миграции, и сверка миграций с моделями не расходится.

## Альтернативы
- **Свой `UserDefinedType` и `func.ST_*`.** Обходится без зависимости, но для полигонов (#92) пришлось бы
  самим писать типы, разбор WKB и GeoJSON, отражение типов для Alembic. Это повторило бы GeoAlchemy2.
- **Хранить `lat`/`lon` двумя числами.** Просто для точек, но не работает с полигонами, не даёт
  GIST-индекса по точке, а расстояния пришлось бы считать вручную.
- **Shapely для геометрии в Python.** Пока не нужна: проверки «точка в зоне» и расстояния делает база.
  Вернёмся к ней, если понадобится разбирать полигоны до записи в базу (#92).

## Последствия
- Новая зависимость `geoalchemy2` в `apps/api`; её обновления проходят как обычные (Dependabot).
- Миграции с геотипами импортируют `geoalchemy2`.
- Модули `geo` (#92) и запросы карты (#94) пишутся тем же способом: функции PostGIS вызываются из
  `repository.py`, наружу отдаются доменные типы (`GeoPoint`), а не значения GeoAlchemy2.

## Дополнение от 2026-10-26: Shapely для проверки полигонов (#92)

Случай из «Альтернатив» наступил: полигоны зон нужно разбирать до записи в базу. Админка должна показать
понятную причину отказа (самопересечение, лишние вершины, вершина вне Минска), а `ST_IsValid` в базе
отвечает только «да» или «нет» и проверяется лишь интеграционным тестом.

- Берём **Shapely** (и `types-shapely` для mypy) в `geo/domain.py`: проверка полигона и правило «можно ли
  завершить аренду в точке» покрываются юнит-тестами без базы.
- База по-прежнему ищет зоны по индексу (`ST_Intersects` по `geography`), Shapely решает только по
  найденным. Shapely считает на плоскости в градусах, база — на сфере. На масштабе города разница между
  ребром на плоскости и дугой большого круга — сантиметры. Точка ровно на ребре, идущем не по меридиану,
  может попасть по разные стороны: база её не найдёт, и зона не засчитается.
- Новая зависимость тянет `numpy`; обновления — через Dependabot, как остальные.
