# ADR-0016. Карта в мобилке: MapLibre React Native и dev-сборка

- Статус: принято
- Дата: 2026-10-26

## Контекст
Главный экран клиента — карта со свободными машинами и зонами завершения (#92). ADR-0003 выбрал MapLibre
и тайлы на основе OpenStreetMap. Для iOS и Android MapLibre есть только как нативный модуль
(`@maplibre/maplibre-react-native`), а нативного кода, которого нет в Expo Go, Expo Go не запустит.
До сих пор вся команда запускала приложение на телефоне через Expo Go, и с картой так больше не выйдет.

## Решение
- **Нативные платформы:** `@maplibre/maplibre-react-native` 11 с его плагином Expo в `app.config.ts`.
  **Веб:** `maplibre-gl`, как в админке. Компонент карты разделён по платформам (`CarMap.tsx` и
  `CarMap.web.tsx`), а данные карты (GeoJSON машин и зон, стили слоёв) строятся общими чистыми функциями.
- **Запуск на телефоне и в эмуляторе — dev-сборка** (`expo-dev-client`). Собираем локально:
  `npm run android --workspace @flagman/mobile` (`expo run:android`) через Android Studio (SDK и JDK из него),
  на macOS — `npm run ios` через Xcode. Папки `android/` и `ios/` генерируются из `app.config.ts`
  (`expo prebuild`) и в git не попадают. EAS Build пока не нужен: нет аккаунта и бюджета, а локальной
  сборки на пилоте хватает.
- **Expo Go остаётся для всего, кроме карты:** `npm run go --workspace @flagman/mobile`. В Expo Go вместо карты
  показывается заглушка «карта работает в dev-сборке», нативный модуль карты загружается лениво и в Expo Go
  не загружается вовсе. Входом, документами и профилем можно заниматься без Android Studio.
- **API с телефона и эмулятора:** `adb reverse tcp:8000 tcp:8000`. Тогда адрес по умолчанию
  `http://localhost:8000` работает и на эмуляторе, и на телефоне по USB, а API в Docker по-прежнему
  слушает только `127.0.0.1`.
- URL стиля карты задаёт `EXPO_PUBLIC_MAP_STYLE_URL` (`apps/mobile/.env.example`). Пустое значение означает
  стиль OpenFreeMap «liberty», тот же, что в админке.

## Альтернативы
- **Карта в WebView с `maplibre-gl`.** Работает в Expo Go, но медленно на слабых Android, жесты
  конфликтуют с экраном, а местоположение и кластеры пришлось бы гонять через мост сообщений.
- **`react-native-maps`.** Работает в Expo Go, но это карты Google и Apple: противоречит ADR-0003.
- **EAS Build вместо локальной сборки.** Не нужен Android Studio, зато нужен аккаунт Expo, очередь
  бесплатного тарифа и пересборка в облаке при каждом изменении нативных зависимостей.

## Последствия
- Чтобы увидеть карту на телефоне, нужен Android Studio (Windows) или Xcode (macOS). Первая сборка идёт
  долго (порядка 10–15 минут), дальше пересобирать нужно только при смене нативных зависимостей или
  `app.config.ts`, а изменения JS приходят через Metro, как в Expo Go.
- `expo start` после установки `expo-dev-client` открывает dev-сборку; для Expo Go есть скрипт `go`
  (`expo start --go`). Веб работает как раньше.
- Обновление Expo SDK (ADR-0008) теперь включает пересборку dev-сборки у всех, кто её использует.
- Скилл `/demo` спрашивает, как показать приложение на телефоне: через Expo Go без карты или через
  dev-сборку в Android Studio.
- Будущий CSP веб-версии должен разрешать адрес стиля и тайлов и `worker-src blob:`, как в админке (ADR-0003).
