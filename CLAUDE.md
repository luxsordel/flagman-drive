# CLAUDE.md — правила для Claude Code в проекте FLAGMAN Drive

Каршеринг электромобилей в Минске. Сейчас — пилот без реальных машин (эмулятор), денег и SMS.
Подробности: `docs/01-vision-and-mvp.md`, архитектура: `docs/02-architecture.md`.

## Перед работой
- Прочитай задачу (GitHub issue) и связанные документы в `docs/`. Если задачи нет — спроси, не придумывай объём.
- Для изменений больше одной-двух правок — сначала план, потом код.
- Не уверен в требованиях — спроси человека, а не угадывай.

## Структура
- `apps/api` — FastAPI, модульный монолит: `src/flagman/<module>/{api,schemas,service,domain,repository,models,ports}.py`
- `apps/mobile` — Expo / React Native / TypeScript (iOS, Android, веб)
- `apps/admin` — React + Vite + TypeScript
- `services/car-emulator` — эмулятор машин (Python)
- `packages/api-client` — **сгенерированный** TS-клиент. Руками не править, перегенерировать.
- `infra` — Docker Compose. `docs` — документация и ADR.

## Архитектурные правила (нарушение = переделка)
- Слои: `api → service → domain / repository`. Бизнес-логика — в `domain`/`service`, не в роутерах и не в ORM.
- Модуль не импортирует чужие `models`/`repository`; только публичные функции чужого `service`.
- Внешние системы (телематика, платежи, SMS, push) — только через интерфейс в `ports.py`.
- Деньги — `int` в копейках BYN. Время — `datetime` с таймзоной, хранение в UTC.
- Переходы статуса аренды — только через машину состояний в `rentals/domain.py`.
- Новое архитектурное решение → ADR в `docs/adr/` по шаблону `0000-template.md`.

## Безопасность (полностью — docs/03-security.md)
- Проверка прав на каждом эндпоинте и **на уровне объекта** (чужие аренды/документы/платежи недоступны).
- Цены и суммы считает только сервер; клиентским суммам не доверять.
- Входные схемы Pydantic с `extra="forbid"`. Никакого SQL из строк.
- Никаких секретов в коде и в коммитах; новые настройки — в `.env.example` без значений.
- Персональные данные и токены не логировать.
- Не ослаблять проверки, не отключать тесты/линтеры/типизацию, чтобы «заработало». Если мешает — скажи.

## Стиль кода
- Код, идентификаторы, комментарии, коммиты — на английском. Документация в `docs/` — на русском.
- Python: ruff (format + lint), mypy --strict, type hints везде, async для I/O.
- TypeScript: strict, без `any`, ESLint + Prettier. Все строки UI — через i18n (ru + en), без хардкода.
- Комментарии объясняют «почему», а не «что». Без мёртвого кода и закомментированных блоков.
- Цвета, шрифты, отступы — только из дизайн-токенов (`docs/07-design-system.md`).

## Тесты
- Бэкенд: pytest. Доменная логика — юнит-тесты без БД; сервисы и API — интеграционные с реальным Postgres (testcontainers).
- Новая логика без тестов не считается готовой. Баг-фикс начинается с теста, воспроизводящего баг.

## Git
- Ветки `feat|fix|chore|docs|refactor/<issue>-<slug>`, коммиты Conventional Commits.
- Не пушить в `main`, не делать force push, не переписывать чужую историю.
- PR — по шаблону `.github/pull_request_template.md`, с `Closes #<issue>`.

## Окружение
- Разработчики на Windows 11. Скрипты должны работать в PowerShell и Git Bash; окончания строк — LF (см. `.gitattributes`).
- Python-зависимости — через `uv`, JS — через `npm`. Не ставить пакеты глобально.
